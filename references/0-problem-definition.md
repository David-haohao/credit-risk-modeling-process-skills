# 阶段 0：问题定义与环境准备

> **可执行脚本**: `scripts/00_env_setup.py` — 运行 `python scripts/00_env_setup.py --help` 查看用法。

## 0.0 阶段信息

- **输入**: 用户需求（数据文件路径、业务背景）
- **核心输出**: `00_modeling_config.yaml`（后续阶段统一读取）
- **展示输出**: `00-output-list.xlsx`（供用户确认和审阅）
- **审计输出**: 环境检查、数据规模预检和配置确认记录
- **耗时记录**: 阶段开始和结束时记录时间戳（精确到分钟）

---

## 0.0.1 输入契约

阶段 0 开始前至少需要：

| 输入 | 必需内容 |
|------|----------|
| 用户需求 | 建模目标、预期模型用途、交付范围 |
| 项目路径 | 原始数据路径、过程代码存放路径、过程文件存放路径、最终报告存放路径 |
| 原始数据定位信息 | 文件路径或数据表位置、文件格式、编码方式 |
| 业务定义 | `Y_label` 含义、样本时间口径、灰样本定义（如有） |

本阶段只确认口径和配置，不对原始数据做不可逆修改。

交付范围必须明确是否包含阶段 6 概率校准、分数尺度变换和风险等级。该选择写入 `enable_stage6_scoring`，不得在阶段 5 结束后才默认推断。

## 0.1 必问信息

阶段 0 必须先问再做。未完成以下确认前，只允许输出配置模板、确认清单和数据预检结果，不得直接进入阶段 1。

需要向用户确认以下信息：

1. **Y_label 含义**
   - Y=1 代表什么
   - Y=0 代表什么
   - 是否存在灰样本；如有，灰样本取值是什么
   - 灰样本处理方式是否为“建模阶段直接剔除，模型完成后单独打分”

2. **样本时间窗口**
   - 数据中哪个字段是时间字段
   - 字段含义是什么（申请日、放款日、账单日等）
   - 样本时间范围
   - 阶段 5 周期 PSI 粒度：周、月或季

3. **缺失值定义**
   - 哪些值需要视为缺失，如 `NaN`、`-9999`、`-999`、空字符串
   - 空字符串、仅空白字符是否按缺失处理
   - 以上定义是否已由用户确认

4. **样本唯一标识方案**
   - 是否存在稳定业务主键，如 `apply_no`
   - 是否存在脱敏主键或主键组合，如手机号/身份证脱敏列、`md5`、`hash`
   - 如需组合字段唯一，记录 `sample_id_source_cols`
   - 只有在以上均不存在且用户明确批准时，才允许使用 `content_hash_confirmed`

5. **模型类型**
   - 必须由用户明确选择 `LR`、`XGB` 或 `LGB`
   - 不得依据特征数量、样本量或脚本默认值自行推断

6. **阶段 1 切分与抽样前置确认**
   - OOT 切分方式由谁决定、是否已确认
   - 是否允许抽样
   - 若允许抽样，抽样方式是什么

## 0.2 模型选择（提前到阶段 0）

**在阶段 0 就必须确认模型选择**，因为后续所有阶段的流程因模型而异。

| 模型 | 样本划分策略 | 验证方式 | 概率含义 |
|------|-------------|----------|----------|
| **LR（逻辑回归）** | Train + OOT（两段划分） | Train 内部 k-fold 交叉验证 + 网格搜索 | 原始概率需在后续阶段检查校准度 |
| **XGBoost / LightGBM** | Train + Test + OOT（三段划分） | Train 训练、Test 调参、OOT 泛化性检验 | 原始概率需在后续阶段检查校准度 |

关键约束：

- 模型选择优先依据业务可解释性要求、有效样本量及 bad 样本数量；特征数量主要影响计算成本与筛选方式，不作为 LR 与 XGB/LGB 的主要选择依据。
- 未经用户确认，不得默认采用 `LR`、`XGB` 或 `LGB`。
- 阶段 4 默认读取 `references/4-model-training.md`；仅当 `model_type` 为 XGB/LGB 时额外读取 `references/4.1-xgb-lgb-tuning.md`。

### 0.2.1 项目交付范围

阶段 0 必须询问用户本次项目是否需要执行阶段 6：

| `enable_stage6_scoring` | 项目范围 | 阶段 5 通过后的路由 |
|-------------------------|----------|---------------------|
| `true` | 继续执行概率校准、分数映射、风险等级及 LR 标准评分卡 | 进入阶段 6，再进入阶段 7 |
| `false` | 模型训练与评估完成后结束建模工作 | 跳过阶段 6，直接进入阶段 7 |

选择 `false` 时，最终报告必须记录阶段 6 未执行及其用户确认原因。XGB/LGB“必须执行概率校准”的要求仅在 `enable_stage6_scoring=true` 时生效。

## 0.3 数据规模预检

在正式全量加载数据前，先做轻量预检。

> **执行**: `python scripts/00_env_setup.py --filepath <数据文件路径>`

建议流程：

1. 先读取表头和少量样本（例如前 5-100 行），识别字段名、时间字段候选、主键候选和缺失值表现形式。
2. 再输出文件大小、列数、估算行数和类型分布。
3. 只有在完成上述轻量预检并拿到用户确认后，才进入正式阶段 1 切分。

性能预警仅用于评估运行时间、内存和是否需要分批处理，不直接决定模型类型，也不构成跳过用户确认的理由。

---

## 0.4 IV 阈值策略

IV 阈值**不应在阶段 0 固定**，而应在阶段 3 先输出 IV 分布后，由用户确认。

阶段 0 仅需告知用户默认策略：

- 默认 IV 阈值 = 0.02
- 阶段 3 会输出各阈值下的特征数量分布
- 用户根据分布情况和业务需求，在阶段 3 最终确认阈值
- 另需单独输出高 IV 告警特征，提示可能的穿越、单箱全好/全坏或异常强变量

### 0.5.1 依赖包清单

以下为全流程所需的所有 Python 包。阶段 0 仅需检查是否已安装，**缺包时提醒用户安装，不自动安装**。

| statsmodels | 0.12+ | 统计检验 |

### 0.5.2 缺失值检查与统一

数据加载后，检查缺失值的实际表示方式，但必须结合 0.1 中用户已确认的缺失定义。

检查内容：

- 各列 `NaN` 数量
- 特殊值（如 `-9999`、`-999`）在各列的出现次数
- 空字符串和仅空白字符的出现情况

统一处理原则：

- 将用户确认的特殊缺失标识统一转换为 `np.nan`
- 如果用户尚未确认缺失定义，只输出检查结果，不得静默套用脚本默认值进入正式流程

### 0.5.3 项目代码目录要求

阶段 0 必须确认 `code_dir`。一旦确认：

1. 将实际执行所需的 `scripts/*.py` 复制到该项目代码目录；
2. 后续阶段以项目目录中的代码为准；
3. 技能目录内脚本可作为模板来源，但不能替代项目交付代码。

## 0.6 阶段 0 输出项

### 0.6.1 核心配置输出

阶段 0 必须生成 `00_modeling_config.yaml`，供阶段 1-7 统一读取。至少包含：

| 配置组 | 必需内容 |
|--------|----------|
| 项目信息 | 项目名称、配置版本、创建时间 |
| 路径配置 | `raw_data_path`、`code_dir`、`intermediate_dir`、`report_dir` |
| 数据定位 | 原始数据路径/表名、文件格式、编码 |
| 字段定义 | `target_col`、`time_col`、`sample_id_col`、`sample_id_source_cols`、`sample_weight_col`、`sample_id_method` |
| 标签定义 | 好样本值、坏样本值、灰样本取值及处理方式 |
| 模型配置 | `model_type`、随机种子；XGB/LGB 额外记录 Trial 数、搜索空间来源和调优模式 |
| 项目范围配置 | `enable_stage6_scoring`、确认原因、确认人和确认时间 |
| 缺失值配置 | 特殊缺失标识列表、`blank_as_missing`、`confirmed_by_user` |
| 样本划分配置 | OOT 方法、Train/Test 划分参数、`sample_method`、`confirmed_by_user`；未确认项标记为 `pending` |
| 模型评估配置 | `psi_period_granularity`；未确认时标记为 `pending` |
| 阶段 3 配置 | IV、相关性、规则变量、高 IV 告警等阈值；未确认项标记为 `pending` |
| 确认记录 | 配置项状态、确认人、确认时间、确认原因 |

### 0.6.2 展示与审计输出

阶段 0 结束时，应明确输出以下记录，统一保存为 `00-output-list.xlsx`：

1. Y_label 含义
2. 模型选择
3. 是否执行阶段 6，以及确认原因
4. 样本唯一标识方案及候选搜索结果
5. 时间字段名称及含义
6. 样本时间窗口
7. 阶段 5 PSI 粒度
8. 缺失值定义
9. 环境检查结果
10. 数据规模预检结果
11. IV 阈值策略说明
12. `code_dir` 已确认且脚本已复制的状态
13. 阶段开始/结束时间戳

### 0.6.4 阶段验收规则

阶段 0 完成前必须检查：

1. 原始数据、过程代码、过程文件和最终报告四类路径均已确认。
2. `Y_label`、时间字段、周期 PSI 观察粒度、模型类型、缺失值定义、样本唯一标识方案均已确认。
3. `sample_id_col` 已通过非空性和唯一性检查，或明确标记由阶段 1 生成；如使用 `content_hash_confirmed`，必须存在用户批准记录。
4. 所有已确认配置同时写入 YAML 和 Excel，二者内容一致。
5. 未确认配置明确标记为 `pending`，并注明最迟确认阶段。
6. `code_dir` 已确认时，项目代码目录内已存在复制后的执行脚本。
