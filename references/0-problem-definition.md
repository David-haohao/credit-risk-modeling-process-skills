# 阶段 0：问题定义与环境准备

> **可执行脚本**: `scripts/00_env_setup.py` — 运行 `python scripts/00_env_setup.py --help` 查看用法。

## 0.0 阶段信息

- **输入**: 用户需求（数据文件路径、业务背景）
- **核心输出**: `00_modeling_config.yaml`（后续阶段统一读取）
- **展示输出**: `00-output-list.xlsx`（供用户确认和审阅）
- **审计输出**: 环境检查、数据规模预检和配置确认记录
- **耗时记录**: 阶段开始和结束时记录时间戳（精确到分钟）

阶段 0 开始前至少需要：

| 输入 | 必需内容 |
|------|----------|
| 用户需求 | 建模目标、预期模型用途、交付范围 |

## 0.1 确认数据基本信息

前置假设：用户提供的数据已经是打好 X 和 Y 的宽表，Y_label 已经构造完成。阶段 0 不需要重新定义或构造 Y。

需要向用户确认以下信息，使用 `AskUserQuestion` 工具：

1. **Y_label 含义**：
   - Y=1 代表什么？（例如：MOB3 内 DPD ≥ 30 天的坏样本）
   - Y=0 代表什么？（例如：表现期内从未触发 DPD ≥ 30 天的好样本）
   - 是否存在中间态标签（如"灰样本"），如有则确认其取值和处理方式（见阶段 1 §1.4）

2. **样本时间窗口**：
   - 数据中用于区分样本时间的字段是哪个且需要明确该字段含义（例如："申请日期"、"放款日期"）
   - 询问样本时间范围（例如：2024-01-01 至 2024-12-31）
   - 询问阶段 5 周期 PSI 的观察粒度：按周、按月或按季；写入 `psi_period_granularity`

3. **缺失值表示方式**：
   - 数据中缺失值以何种形式存在？
   - 常见：`NaN`、`-9999`、`-999`、空字符串 `""`

4. **样本唯一标识**：
   - 确认能够唯一标识一条建模样本的字段，写入 `sample_id_col`
   - 优先使用已存在的稳定业务主键或脱敏主键
   - 如果需要多个字段组合才能唯一，记录 `sample_id_source_cols`
   - 唯一标识仅用于样本追溯，禁止作为模型特征
   - 如果原始数据不存在稳定唯一标识，阶段 1 必须生成并固化 `sample_id`，后续阶段不得重新生成

## 0.2 模型选择（提前到阶段 0）

**在阶段 0 就必须确认模型选择**，因为后续所有阶段的流程因模型而异。

使用 `AskUserQuestion` 工具向用户确认：

| 模型 | 样本划分策略 | 验证方式 | 概率含义 |
|------|-------------|----------|----------|
| **LR（逻辑回归）** | Train + OOT（两段划分） | Train 内部 k-fold 交叉验证 + 网格搜索 | 原始概率需在后续阶段检查校准度 |
| **XGBoost / LightGBM** | Train + Test + OOT（三段划分） | Train 训练、Test 调参、OOT 泛化性检验 | 原始概率需在后续阶段检查校准度 |

**关键差异**：
- 模型选择优先依据业务可解释性要求、有效样本量及 bad 样本数量；特征数量主要影响计算成本与筛选方式，不作为 LR 与 XGB/LGB 的主要选择依据
- LR 超参数少（主要是正则化强度 C、L1/L2 等），通常不需要独立的 Test 集，k-fold 在 Train 内部完成即可
- XGB/LGB 超参数多，需要独立的 Test 集用于 Optuna 贝叶斯调参，OOT 用于最终泛化性检验
- LR 与 XGB/LGB 均输出原始概率；是否能够解释为真实坏账率，由阶段 5 校准评估决定，阶段 6 仅在需要时执行概率校准
- 阶段 4 默认读取 `references/4-model-training.md`；仅当 `model_type` 为 XGB/LGB 时额外读取 `references/4.1-xgb-lgb-tuning.md`

## 0.3 数据规模预检

在正式加载数据前，先快速检查数据规模，提前预警性能风险。

> **执行**: `python scripts/00_env_setup.py --filepath <数据文件路径>`

检查项：
- 文件大小（MB）
- 列数
- 行数（估算）
- 特征类型分布

**性能预警处理**：
- 数据规模预检仅用于评估运行时间、内存和是否需要分批处理，不直接决定模型类型
- 是否执行阶段 3 预筛选，由阶段 2 数据质量结果、无效特征情况和实际运行成本决定
- 使用 `toad.Combiner` 前可基于代表性样本与特征进行性能测试；性能不可接受时采用分批分箱、减少候选特征或替换分箱实现

## 0.4 IV 阈值策略

IV 阈值**不应在阶段 0 固定**，而应在阶段 3 先输出 IV 分布后，由用户确认。

阶段 0 仅需告知用户默认策略：
- 默认 IV 阈值 = 0.02（适用于大多数场景）
- 阶段 3 会输出各阈值下的特征数量分布（如 IV >= 0.05 有 N 个，IV >= 0.02 有 M 个，IV >= 0.01 有 K 个）
- 用户根据分布情况和业务需求，在阶段 3 最终确认阈值

## 0.5 环境初始化与依赖检查

### 0.5.1 依赖包清单

以下为全流程所需的所有 Python 包。阶段 0 仅需检查是否已安装，**缺包时提醒用户安装，不自动安装**。

| 包 | 最低版本 | 用途 |
|----|---------|------|
| pandas | 1.0+ | 数据处理 |
| numpy | 1.18+ | 数值计算 |
| matplotlib | 3.0+ | 绑图 |
| seaborn | 0.10+ | 统计可视化 |
| plotly | 5.0+ | 交互式图表 |
| toad | 0.1.0+ | 分箱/WOE/评分卡 |
| xgboost | 1.5+ | 树模型 |
| lightgbm | 3.0+ | 树模型 |
| optuna | 2.0+ | 贝叶斯超参调优 |
| sklearn | 0.24+ | 机器学习 |
| scipy | 1.5+ | 科学计算 |
| statsmodels | 0.12+ | 统计检验 |

> **执行**: `python scripts/00_env_setup.py --check-packages`

### 0.5.2 中文/图表环境配置

- 尝试配置中文字体（SimHei），如无则回退英文并提醒用户
- seaborn 样式设为 `whitegrid`
- Plotly 无需额外配置，交互式图表默认支持中文

### 0.5.3 缺失值检查与统一

数据加载后，检查缺失值的实际表示方式（配合 0.1 中用户的确认结果）。

> **执行**: `python scripts/00_env_setup.py --filepath <路径> --missing-markers -9999 -999`

检查内容：
- 各列 NaN 数量
- 特殊值（-9999, -999, -99999）在各列的出现次数

统一处理：将用户确认的特殊缺失标识统一转换为 `np.nan`。

### 0.5.4 数据加载

支持格式：CSV（utf-8-sig 编码）、Excel（.xlsx/.xls）、Parquet（.parquet）。

## 0.6 阶段 0 输出项

### 0.6.1 核心配置输出

阶段 0 必须生成 `00_modeling_config.yaml`，供阶段 1-7 统一读取。至少包含：

| 配置组 | 必需内容 |
|--------|----------|
| 项目信息 | 项目名称、配置版本、创建时间 |
| 路径配置 | `raw_data_path`、`code_dir`、`intermediate_dir`、`report_dir` |
| 数据定位 | 原始数据路径/表名、文件格式、编码 |
| 字段定义 | `target_col`、`time_col`、`sample_id_col`、`sample_id_source_cols`、`sample_weight_col` |
| 标签定义 | 好样本值、坏样本值、灰样本取值及处理方式 |
| 模型配置 | `model_type`、随机种子；XGB/LGB 额外记录 Trial 数、搜索空间来源和调优模式 |
| 缺失值配置 | 特殊缺失标识列表 |
| 样本划分配置 | OOT 方法、Train/Test 划分参数；未确认项标记为 `pending` |
| 模型评估配置 | `psi_period_granularity`（`week` / `month` / `quarter`）；未确认时标记为 `pending` |
| 阶段 3 配置 | IV、相关性、规则变量等阈值；未确认项标记为 `pending` |
| 评分卡配置 | base_score、base_odds、PDO 等；未确认项标记为 `pending` |
| 确认记录 | 配置项状态、确认人、确认时间、确认原因 |

后续阶段产生新的用户确认结果时，必须回写同一配置文件并更新配置版本，不得只保存在对话或代码常量中。

### 0.6.2 展示与审计输出

阶段 0 结束时，应明确输出以下记录，统一保存为 `00-output-list.xlsx`：

1. Y_label 含义（Y=1 代表什么，Y=0 代表什么，有无灰样本）
2. **模型选择（LR / XGBoost / LightGBM）**
3. 样本唯一标识字段及唯一性检查结果
4. 时间字段名称及含义
5. 样本时间窗口（起止日期）
6. 阶段 5 周期 PSI 观察粒度（周 / 月 / 季）
7. 缺失值表示方式（NaN / -9999 / 其他）
8. 环境检查结果（依赖包状态）
9. 数据规模预检结果（行数、列数、文件大小、性能预警）
10. IV 阈值策略说明（默认 0.02，阶段 3 确认）
11. 阶段开始/结束时间戳

### 0.6.3 输出文件清单

| 文件 | 说明 |
|------|------|
| `00_modeling_config.yaml` | 后续阶段统一读取的机器可读配置 |
| `00-output-list.xlsx` | 配置、检查结果和用户确认记录汇总 |
| `00_environment_check.csv` | 依赖包及运行环境检查明细 |
| `00_data_profile.csv` | 文件规模、字段数量、类型和基础质量预检 |

### 0.6.4 阶段验收规则

阶段 0 完成前必须检查：

1. 原始数据、过程代码、过程文件和最终报告四类路径均已确认。
2. Y_label、时间字段、周期 PSI 观察粒度、模型类型和样本唯一标识均已确认。
3. `sample_id_col` 已通过非空性和唯一性检查，或明确标记由阶段 1 生成。
4. 所有已确认配置同时写入 YAML 和 Excel，二者内容一致。
5. 未确认配置明确标记为 `pending`，并注明最迟确认阶段。
6. 配置文件可被正常解析，不依赖代码中的硬编码常量。
