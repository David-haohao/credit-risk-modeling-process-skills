# 阶段 4.1：XGB/LGB 参数调优

> 仅当阶段 0 确认 `model_type` 为 XGB 或 LGB 时读取。本文件补充 `4-model-training.md`，不得单独执行。

## 4.1.1 默认调优契约

- Train 用于拟合；Test 用于调参和 Early Stopping；OOT 仅用于最终泛化评估。
- 调优前必须确认模型类型、Trial 数、搜索空间来源、采样策略和随机种子。
- Test 被反复用于参数选择，因此属于 tuning set，不应描述为独立最终验证集。
- 若反复人工缩小搜索空间，应记录调整轮次和理由，避免持续对 Test 过拟合。

推荐调优流程：

```text
建立保守参数基线
→ 确认搜索空间和 Trial 数
→ Optuna 搜索
→ 审阅效果、过拟合差值、最佳迭代轮数和参数重要性
→ 确认最终 Trial
→ 使用完整 Train 固化最终模型
```

建议建立基线模型，并记录 Train/Test AUC、Test KS、AUC Gap、最佳迭代轮数和耗时。基线用于判断 Optuna 是否产生实际改善，不参与 OOT 比较；未建立基线时应在输出汇总中说明。

每个 Trial 默认记录：

| 字段 | 说明 |
|------|------|
| Trial 编号、状态、开始/结束时间、耗时 | 运行过程 |
| Train/Test AUC、Test KS、AUC Gap | 效果与过拟合诊断 |
| 历史最佳 Test AUC、本轮改善量 | 搜索收敛过程 |
| 最佳迭代轮数、是否触及轮数上限 | Early Stopping 结果 |
| 全部参数 | 参数组合 |

默认 Trial 选择以 Test AUC 为主，同时审阅 Test KS、AUC Gap、最佳迭代轮数和耗时。若人工选择的 Trial 不是自动最佳项，必须记录原因。

### 过拟合软约束

- `allowed_auc_gap` 为软约束，不作为自动删除 Trial 的硬阈值；默认建议值为 `0.03`，执行前允许用户调整。
- AUC Gap 超过允许值时，将 Trial 标记为过拟合候选，并在最终 Trial 选择时说明是否接受。
- 如需将过拟合风险纳入自动排序，可按需使用：

```text
selection_score =
    Test AUC
    - gap_penalty × max(AUC Gap - allowed_auc_gap, 0)
```

`gap_penalty` 和 selection score 必须由用户确认后启用。默认脚本仍以 Test AUC 选择自动最佳 Trial。

### 调优停止判断

完成计划 Trial 后至少检查：

1. 历史最佳 Test AUC 是否长时间无改善。
2. 最佳 Trial 是否反复触及搜索边界。
3. 参数重要性是否稳定，是否存在明显无效参数。
4. 最佳迭代轮数是否经常触及 `n_estimators` 上限。
5. 高 Test AUC Trial 是否普遍伴随较大 AUC Gap。

若仍需继续搜索，应记录原因并确认追加 Trial 数或调整搜索空间；不得参考 OOT 决定是否继续。

## 4.1.2 默认搜索空间

### XGBoost

| 参数 | 默认范围 |
|------|----------|
| `n_estimators` | 100–500 |
| `learning_rate` | 0.01–0.2，log |
| `max_depth` | 3–8 |
| `subsample` | 0.6–1.0 |
| `colsample_bytree` | 0.6–1.0 |
| `min_child_weight` | 1–20 |
| `reg_alpha` / `reg_lambda` | 1e-3–10，log |

### LightGBM

| 参数 | 默认范围 |
|------|----------|
| `num_leaves` | 8–128 |
| `max_depth` | 3–12 |
| `min_data_in_leaf` | 5–100 |
| `learning_rate` | 0.005–0.2，log |
| `n_estimators` | 50–1000 |
| `feature_fraction` / `bagging_fraction` | 0.5–1.0 |
| `lambda_l1` / `lambda_l2` | 1e-4–100，log |

当 `max_depth > 0` 时，LGB 应约束 `num_leaves <= 2^max_depth`。

`scale_pos_weight` 不应无条件使用 `n_good/n_bad`。脚本默认使用 `1`，并记录 `n_good/n_bad` 作为候选值；如需比较两者，应由用户确认后分别运行并结合区分度和后续校准结果选择。

## 4.1.3 最终模型固化

- 最终 Trial 必须由用户确认，或明确采用自动最佳 Trial。
- 最终模型使用已确认 Trial 的其他参数，并将树数量设置为 `best_iteration + 1`。
- 使用完整 Train 重新训练最终模型；Test 不参与最终拟合，OOT 仅用于最终预测。
- 最终模型配置必须记录模型类型、参数、最佳迭代轮数、随机种子、样本权重、`scale_pos_weight` 和库版本。

## 4.1.4 默认核心输出

- `04_optuna_trials.csv` / `.xlsx`
- `04_optuna_history.png`
- `04_optuna_param_importance.csv` / `.png`
- `04_best_params.json`
- `04_optuna_study.pkl`
- `04_feature_importance.csv`

实际搜索空间、Trial 数、采样配置、随机种子和库版本必须写入 `04_model_metadata.json`；支持配置持久化时，同时写入 `04_optuna_search_space.json`。

建议在 `04-output-list.xlsx` 中至少展示：

1. 基线与最终 Trial 的 Train/Test AUC、Test KS、AUC Gap 和最佳迭代轮数。
2. Top Trial 参数及核心指标。
3. 历史最佳 Test AUC 变化。
4. 参数重要性。
5. 最终 Trial 选择理由。

## 4.1.5 建议能力

以下能力在训练成本允许且需要进一步优化时建议启用，但不是默认强制项：

- 基线模型后执行粗搜索与精细搜索：
  - 粗搜索使用较宽范围探索有效区域。
  - 精细搜索只能根据粗搜索结果缩小范围，不得参考 OOT。
  - 每次调整搜索空间均记录调整前后范围和理由。
- 保存明确的 `study_name` 和 SQLite/RDB Storage，以支持断点续跑。
- 输出 Train/Test AUC、AUC Gap、Trial 状态和最佳迭代轮数分布图。

## 4.1.6 高级可选能力

以下能力仅在用户确认、训练成本或审计要求需要时启用，不作为默认强制项：

- 带 AUC Gap 惩罚的 `selection_score`
- MedianPruner / HyperbandPruner 与 intermediate values
- 并行调优和 Optuna Dashboard
- 多目标 Study 与 Pareto Front
- Slice、Contour、Parallel Coordinate、Timeline 等扩展图表

启用 Pruner 时必须保存 intermediate values；启用多目标模式时必须输出 Pareto Front 并由用户确认最终 Trial。所有高级能力均需记录配置、适用原因和失败原因。

## 4.1.7 验收

1. 实际模型实现与 `model_type` 一致。
2. Test 仅作为 tuning set，OOT 未参与调参。
3. 每个 Trial 和最终模型的核心指标可追溯；建立基线时，基线指标同时可追溯。
4. 每个 Trial 的参数、状态、耗时和核心指标完整。
5. 最终模型使用已确认参数和 `best_iteration + 1`。
6. 最终 Trial 的选择理由已记录；非自动最佳 Trial 有人工确认。
7. 是否继续搜索的判断未使用 OOT。
8. 不适用的建议或高级能力不应被误报为缺失。
